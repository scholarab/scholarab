## Commands

- `npm run ci`: lint, unit tests, build, type checks. Run it before every push.
- `npm run test:e2e`: Playwright. CI runs it too, so run it locally before pushing changes to /match, the directories or /saved.
- `npm run ship-check -- origin/main`: run before shipping and complete every RUN line it prints.
- `npm test -- path/to/file.test.ts`: a single Vitest file. Count tests by running the suite, never by grepping.

## Pitfalls

- The build reads the JSON in `src/data/` (`DATABASE_URL=` is blanked in `npm run build`). `npm run dev` reads the database and can disagree with production. Measure and verify against the build (`dist/`), never the dev server.
- `active: false` does not mean closed; `concluded: true` does. Status comes from deadline, openDate and those flags via `src/lib/status.ts` and `list-core.ts`. Never invent an openDate.
- A deleted or renamed page needs a 301 in `public/_redirects` to a real surviving page, in both slash forms. The build validates the file.
- No em dashes in `src/`, `scripts/`, workflows or docs: validate-data fails the build on one.
- Builds run with `TZ=America/Edmonton`. Never serialize a build-time date as milliseconds; client code recomputes from the ISO string in the visitor's timezone.
- Cloudflare email obfuscation rewrites `mailto:` anchors. Wrap them with `emailOff()` or `<!--email_off-->` comments.
- `src/data/lastmod.json` is committed and regenerated by the build. Commit it with the page change that moved it.
- Other agents edit `src/data/*.json` concurrently in this checkout. Stage only your own hunks and diff listing ids against HEAD before committing a data file.
- Tests never live in `src/pages/` (Astro would route them).
- Automated sync commits use `[skip actions]`, not `[skip ci]`, so Cloudflare Pages still deploys.
- Commit subject is always `Bug fixes, minor improvements, and more.`
